BoilStream 0.9.0 — 2026-11-08

Breaking client protocol release for DuckDB v2.0.0 (native, WASM EH and pthread).
The maintainer requested publication of 0.9.0. Earlier assessments remain in Git
history; this document describes the current release scope.

Compatibility
- Requires a compatible encrypted-protocol BoilStream server and an independently
  provisioned X25519 installation public key, configured per DuckDB connection.
- No legacy header-signing fallback. Authentication and secret-management bodies
  are encrypted/authenticated; this is not encryption of all Quack query traffic.
- HTTPS remains deployment policy. The protocol is tested over plaintext loopback
  with response security headers removed.
- Threaded Quack needs the paired source-built shared-memory artifact. Load dynamic
  extensions before enabling query workers. WASM MVP remains excluded.
  See test/wasm/QUACK_COMPATIBILITY.md.

Verification
- Actual private-server protocol gate: six cases passed, zero ignored, including
  loaded native/EH/pthread clients, registration/MFA, login, tenant isolation,
  revocation, explicit renewal and rejected tampered replies.
- Transport tests cover replay, duplicate admission and unknown mutation outcomes.
- Public native security tests, Rust audits, WASM/browser tests, format/tidy and
  Linux amd64/arm64, macOS arm64, Windows MSVC/MinGW and both WASM distribution
  jobs pass for the implementation candidate bae69ee. Release documentation only
  changes after that candidate; release-head GitHub checks must also pass.
- Fresh local cargo audit --deny warnings passes both production lockfiles:
  opaque-client (102 dependencies) and protocol-client (48 dependencies).
- Native C++21 suites, Rust27 tests, WASM C ABI36/37 assertions and the retained
  FFI runner/harness checks remain applicable to the unchanged implementation.

Three inline release reviews (same author, distinct angles)
1. Security: configured server identity precedes credentials; verified body
   metadata replaces unavailable browser headers. No fallback, secret test key,
   private server code or installation private key is added to the release.
2. Test coverage: real native/EH/pthread authenticated exchanges are distinct from
   public negative tests. No skipped authenticated case is counted as a pass;
   transport replay tests and loaded-client tests retain their stated scopes.
3. Release/compatibility: 0.9.0 communicates a breaking protocol change. Existing
   tags remain immutable, the community descriptor pins the exact source commit,
   and DuckDB's normal central build/sign/deploy process remains unchanged.

Publishing
The GitHub release publishes source. Community installation requires the separate
0.9.0 descriptor PR to merge and central deployment to succeed. Do not describe a
submitted PR or GitHub tag as completed community deployment.
